# Results Analysis Parameters (T1)

Companion to [results-analysis.md](results-analysis.md) — the concrete
schema and source-file rules `src/analyse_results.py` is built against,
decided here so code and doc can't drift apart silently.

## Source files (read-only, trailing JSON line(s) per dataset)

Each file already ends with one `json.dumps(row)` line per dataset —
this is the established convention across every prior stage
(`eda.py`, `baselines.py`, `arima_model.py`, `evaluate_model.py`), so the
loader just needs to find and parse those lines, not the surrounding
human-readable text.

| Source | Path | Expected keys per row |
|---|---|---|
| EDA | `reports/eda/eda_cross_domain_summary.txt` | `dataset`, `n`, `frequency`, `adf_p_d0`, `adf_p_d1`, `suggested_d`, `dominant_acf_lag`, `dominant_pacf_lag`, `cv`, `seasonal_strength`, `visible_seasonality`, `has_ground_truth` |
| Baselines | `reports/baselines/baselines_cross_domain_summary.txt` | `dataset`, `n_train`, `n_test`, `ses_alpha`, `naive_mae`, `naive_rmse`, `naive_mape`, `historical_mean_mae`, `historical_mean_rmse`, `historical_mean_mape`, `moving_average_mae`, `moving_average_rmse`, `moving_average_mape`, `ses_mae`, `ses_rmse`, `ses_mape` |
| ARIMA | `reports/arima/arima_cross_domain_summary.txt` | `dataset`, `failed`, `n_train`, `n_test`, `d`, `p_max`, `q_max`, `order`, `aic_bic_agree`, `mae`, `rmse`, `mape` |
| Evaluation | `reports/evaluation/evaluation_cross_domain_summary.txt` | `dataset`, `n_test`, `arima_wins`, `baseline_wins`, `no_significant_difference`, `no_test_possible` |

## Parsing rule

- Read each file's lines; a line is a data row if `json.loads(line)`
  succeeds and the result is a dict containing a `dataset` key (skips the
  human-readable header/table lines above it without needing to know
  their exact format).
- Merge all four sources on `dataset` (inner join — a dataset must appear
  in all four to get a master-table row; see Constraints).
- If any expected key (table above) is missing from a parsed row, **raise
  immediately** naming the source file and missing key — never fill a
  blank/NaN silently (spec risk: "master table could silently go stale").

## Column naming in the merged table

Source column names are kept as-is except where two sources collide:
- ARIMA's `mae`/`rmse`/`mape`/`n_train`/`n_test` → prefixed `arima_mae`,
  `arima_rmse`, `arima_mape`, `arima_n_train`, `arima_n_test`.
- Baselines' `n_train`/`n_test` → prefixed `baselines_n_train`,
  `baselines_n_test` (kept alongside ARIMA's and evaluation's `n_test`
  as a cross-check that all three stages agree on split size — they
  should always be equal since all three reuse the identical
  `TRAIN_FRACTION=0.8` rule; a mismatch would itself be worth surfacing,
  not hidden by collapsing to one column).
- Evaluation's `n_test` → `evaluation_n_test`.
- EDA's `dataset` is the join key; kept unprefixed as `dataset`.

## Inclusion rule

A dataset is included in the master table only if it appears in **all
four** source summaries (i.e. it passed the quality gate, produced a
successful ARIMA fit, and was evaluated). Given all four final datasets
currently succeed at every stage, this is expected to include all four;
if a future run has a dataset missing from any one source, it's excluded
from the master table with a stated reason in the table's accompanying
`.txt`, not silently dropped without a trace.

## Output paths

- `reports/analysis/master_evidence_table.csv` — one row per dataset, all
  merged columns.
- `reports/analysis/master_evidence_table.txt` — same data, human-readable
  (pipe-delimited table, matching every prior stage's `.txt` summary
  style).
- `reports/analysis/rq1_rq2_analysis.md` — the narrative document (T4,
  written directly, not generated by the script).

## Narrative document structure (T4)

Fixed section order, each required (Success Criteria):

1. **Status banner** — DM provisional status restated at the very top,
   not just in Limitations.
2. **RQ1 verdict** — quoted RQ1 wording, per-dataset and overall answer,
   citing `reports/evaluation/*_evaluation.txt` and the master table.
3. **RQ2: cross-domain performance variation** — quoted RQ2 wording,
   domain-by-domain pattern, explicit naming of the underperforming
   domain(s), citing EDA + ARIMA + evaluation evidence together.
4. **Aviation MRO workforce-planning implications** — discursive,
   evidence-grounded, repeatedly qualified as analogy/inference rather
   than direct MRO evidence (no MRO dataset was tested).
5. **Limitations** — DM provisional status, MAE-only significance
   testing, per-dataset-not-global correction, `call_center_emea_2021_2025`'s
   test-set power, plain-ARIMA-only scope, pending generated-vs-real
   dataset question.
